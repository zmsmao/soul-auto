# SoulBot 2.0 产品定义

<!-- impeccable:product-schema 1 -->

## Platform

android

## Users

主要用户是在自己的 Android 手机上配置、运行并监督 Soul 自动化辅助工具的个人用户。

## Product Purpose

SoulBot 将 Soul 页面自动化、聊天上下文管理、模型回复生成与本地诊断整合为一个可配置、可监督的 Android 应用。核心价值不是无人监管地持续发送消息，而是在清楚展示当前任务与运行状态的前提下，减少重复页面操作，并让回复更能承接对话。

## Core Workflows

- **星球与聊天**：优先处理奇遇铃、新招呼和未读会话；空闲时进入星球执行灵魂匹配。
- **广场与私聊**：优先处理奇遇铃、新招呼和未读会话；空闲时扫描同城广场并尝试主动私聊。
- 两种模式互斥。奇遇铃、未读消息等高优先级事件可以抢占空闲任务。
- 悬浮控制器负责展示状态、下一步动作、倒计时和停止入口；导航及设置页面不应接管自动化状态。

## 2.0 Capability Set

- Android AccessibilityService 页面识别、消息读取/发送、导航与设备适配诊断。
- 多轮会话上下文、短答承接、话题交接与会话状态跟踪。
- 自适应回复生成深度：轻量生成、审核、分析与审核按可观察的消息信号选择。
- 低信息回复节奏控制；重要问题、情绪和结束信号优先于等待规则。
- 个人资料卡按字段控制主动公开、被问时回答或不公开。
- 未读列表预览的优先级识别；同优先级继续按消息时间与列表顺序处理。
- 最多 5 个 OpenAI 兼容模型端点的配置、排序、测试、故障切换和冷却。
- 人工回复风格学习、分场景反馈与聊天回放盲选评估。
- 联系人历史聊天存储；独立的证据型结构化联系人记忆与可选提取。
- Material 3 日夜间主题、悬浮控制器、脱敏诊断日志和设备兼容性工具。

## Product Constraints

- 主要依赖 Soul 当前可访问的页面节点、控件标识和可见文本；页面改版可能导致识别失败。
- 图片、表情包和未暴露文字的复杂卡片不保证可准确解析。
- 语音转写依赖 Soul 客户端提供的能力，不自行承诺离线语音识别。
- 模型生成需要配置兼容接口；调用会消耗对应服务商额度，网络或供应商差异会影响结果。
- 聊天数据和 API 配置保存在应用私有目录；用户主动导出的聊天、回放和诊断文件可能包含敏感信息。
- 结构化联系人记忆提取默认关闭，启用后会把符合条件的入站消息提交给所选模型服务；该结构化记忆当前不作为自动回复的生成上下文。
- Android 后台限制、无障碍权限和悬浮窗权限会影响持续运行。

## Brand Commitments

产品名称为 **SoulBot 自动助手**。界面文案使用简体中文，语气直白、清晰、可操作；品牌视觉采用克制的靛蓝/紫色强调色、柔和表面色和清晰层级。

## Product Principles

- 将当前状态、风险提示和下一步可执行动作放在显眼位置。
- 区分高频运行控制、低频配置和具有破坏性的清理操作。
- 让模型策略、页面操作和任务调度分别承担清晰职责。
- 允许普通聊天自然停顿，不把“每轮都要回复”或“每轮都要提问”当作目标。
- 不把推测当作联系人事实；个人资料只使用已填写且允许披露的字段。
- 联系人记忆必须有证据、可确认、可修正、可拒绝和可删除。
- 保留人工停止与监督入口，不把回放测试候选自动发送给 Soul。
- UI 整理不应顺手改变任务优先级、模型路由、数据库语义或聊天策略。
