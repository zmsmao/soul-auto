# SoulBot Android 使用指南

SoulBot 是运行在 Android 手机上的 Soul 自动化辅助工具。应用通过 Android 无障碍服务识别 Soul 中可访问的页面和聊天内容，并使用用户配置的模型服务辅助生成回复。

当前版本：**2.2.3**。

## 系统要求

- Android 8.0（API 26）及以上。
- 已安装并登录 Soul。
- 可访问的 OpenAI Chat Completions 兼容模型服务。
- 网络连接、无障碍服务和悬浮窗权限。

## 安装应用

1. 打开 [GitHub Releases](https://github.com/zmsmao/soul-pilot/releases)。
2. 下载最新版本的 `SoulBot-版本号.apk`。
3. 在 Android 设备上安装 APK。
4. 首次启动时按系统提示授予所需权限。

### 从旧 Debug 包迁移

早期测试版使用 Android Debug 签名，与正式版本的签名不同。第一次安装正式版前，请先在应用中导出需要保留的聊天数据和设置，然后卸载旧 Debug 包，再安装正式版。卸载会清除应用私有目录中的本地数据，请务必先备份。

后续正式版本使用同一发布签名，可以直接覆盖安装。

## 首次配置

1. **配置模型服务**：进入「模型与 API」，填写服务商、API 根地址、模型名称和 API Key，保存后使用测试功能确认可用。
2. **填写个人资料**：只填写真实且希望在聊天中使用的信息，并按字段设置公开范围。
3. **选择自动化模式**：根据需要选择「星球与聊天」或「广场与私聊」。
4. **配置任务参数**：按自己的使用习惯设置任务和等待时间。
5. **开启系统权限**：在 Android 系统设置中开启 SoulBot 无障碍服务和悬浮窗权限。
6. **检查设备适配**：首次使用建议进入设备诊断页面，确认 Soul 当前页面可被识别。
7. **启动任务**：打开 Soul，显示悬浮控制器，确认当前状态后再启动任务。

## 页面视觉系统（2.2.3）

2.2.3 对首页以外的功能页面进行了第二轮视觉重构，重点不是只统一圆角和控件，而是统一整套页面的背景、标题和内容层级：

- 内页使用与首页同色系的浅蓝渐变画布，从顶部柔和蓝色过渡至底部近白色，并叠加低对比度柔光层次。
- 顶部 Toolbar 改为透明背景，与页面画布连续衔接，状态栏颜色同步到画布顶部。
- 页面主标题统一字号、字重和蓝色竖向强调标记；标题说明与正文维持明确的层级关系。
- 内容卡片采用白色表面、统一圆角和轻量描边，并增加克制的悬浮层次，避免纯色背景上卡片彼此粘连。
- 设置、模型、联系人、联系人详情、个人资料、回放、回复学习、备份、运行环境、设备诊断、运行日志、历史记录和版本更新页面均接入共享画布。
- 没有独立标题区的工具页和列表页保留原有信息密度，使用相同画布和卡片表面，不强行添加空洞的大型 Banner。
- 首页消息队列布局与既有首页背景保持不变。

本次仅修改 Android XML、Drawable、颜色和主题资源，以及版本说明；不修改 Activity/Kotlin 业务逻辑、View ID、数据结构、数据库或自动化流程，也不修改 Prompt、人设、模型路由、AI 回复判定、回复生成规则、聊天节奏、联系人记忆和人工回复学习。无需本地数据迁移。

## 联系人队列与页面调度（2.2.1）

普通私聊使用联系人级持久化 FIFO 队列。2.2.1 调整了联系人列表的发现和返回逻辑：

- 只有检测到新一轮未读红点时，才检查当前可见的联系人页，并把当前页上明确标记未读的联系人加入队列。
- 不再为了清除或确认 Soul 的全局未读红点而逐页遍历整个联系人列表，也不再每隔 30 秒重复全量扫描。
- 当前可见页没有已排队联系人时，只有 FIFO 中确实存在一个待处理联系人需要定位，才会继续翻页寻找该联系人；翻页经过的其他联系人不会被批量加入队列。
- 不再为了开始检查而自动把联系人列表滚动到顶部。
- FIFO 队列没有待处理任务后，直接返回当前模式的空闲页面；在「广场与私聊」模式下返回同城广场。全局红点暂时残留不会触发重复进列表。
- 队列头部处于失败等待或发送结果待确认状态时，仍按原有退避、核验和阻塞规则处理，不会为了绕过队列而丢弃任务。

此调整只涉及联系人发现、队列调度和页面导航，不修改 Prompt、人设、模型路由、回复生成、聊天节奏、联系人记忆或人工回复学习。

## 同城广场安全浏览（2.2.0）

同城广场会先扫描动态卡片，再决定是否尝试打开用户主页。2.2.0 增加了直播/活动卡片防误点处理：

- 检查卡片无障碍节点中的文本和 Content Description，重点识别头像附近的「活动中」「直播中」等状态标识。
- 识别「正在热聊」与「一键加入」等组合活动入口；命中直播或活动特征的卡片会在点击前跳过。
- 普通动态正文单独提到「直播」不会因此被过滤，避免误伤正常动态。
- 打开主页时只接受头像本身或头像附近、尺寸受限的可点击目标；不再向上点击可能覆盖整张卡片的父节点，也不使用不安全的坐标点击兜底。
- 点击后验证当前页面。只有确认进入用户主页，才继续原有主页和私聊流程。
- 如果进入直播间或无法确认目标页面，会停止当前卡片处理并进行有限次数的返回恢复；无法恢复时停止本轮广场浏览，避免一直挂在直播间或重复误点。

过滤能力依赖 Soul 当前版本向 Android 无障碍服务暴露的节点信息。若某种卡片样式没有暴露可识别标识，程序仍会通过安全点击限制降低误触风险；无法确认点击目标时应跳过。此功能尚需在不同 Soul 版本和设备上持续验证，不能保证识别所有未来出现的直播卡片。

## 联系人 FIFO 队列（2.1.1 起）

普通私聊使用联系人级 FIFO 队列：

- 新一轮未读检查只从当前可见联系人页识别联系人和未读状态，并按发现顺序建立待处理任务。
- 后续页面滚动只用于定位已经在队列中的具体联系人，不会把经过页面上的联系人自动加入队列。
- 应用逐个处理联系人任务；进入对应私聊后才读取聊天内容，交给原有上下文和回复流程。
- 同一联系人对应一个队列任务，不会因为该联系人连续收到多条消息而为每条消息重复创建任务。
- 任务状态会持久化。遇到可重试的失败时，任务会保留并在退避时间后重试；应用重启后可恢复未完成任务。
- 如果发送结果无法确定，队列会暂停后续处理，等待人工确认发送状态，避免直接重复发送。
- 官方通知、系统通知等非普通私聊内容会被过滤；其他特殊流程仍使用各自原有处理机制。

联系人任务队列只保存任务标识和处理状态，不保存消息正文、预览或消息时间。实际聊天内容仍在进入私聊后读取，并继续供原有上下文、联系人记忆和人工回复学习流程使用。

## 版本更新

SoulBot 可以在应用内检查并安装 GitHub 正式版更新：

1. 打开「设置 → 版本更新」可随时手动检查。
2. 应用首页每 24 小时最多自动检查一次；发现新版本时会显示提示。
3. 在版本更新页面查看版本号、发布时间和更新说明，点击下载后等待 APK 完成校验。
4. 应用会校验下载文件的 SHA-256、包名、版本号、versionCode 和正式发布签名。
5. 点击「安装更新」后，Android 系统安装器会要求确认。首次使用时，系统可能要求先允许 SoulBot 安装未知应用。

下载和校验可自动完成，但 Android 不允许普通应用静默安装 APK，最后一步必须由用户在系统安装器中确认。安装前请先停止正在运行的自动化任务。正式签名版本可以覆盖更新并保留本地数据；旧 Debug 包需先按上文迁移步骤备份并卸载。

## 使用与停止

悬浮控制器用于查看运行状态、当前动作和下一步提示。需要人工接管设备或停止自动化时，使用控制器中的停止入口。停止后，应用不会因普通工作线程恢复而主动重新启动用户已停止的任务。

请在运行期间保留监督，不要在未检查聊天对象和当前页面的情况下长时间无人看管。

## 聊天记录与备份

应用可在本地保存联系人聊天记录，并提供导出、导入和清理功能。导出文件可能包含聊天正文和联系人信息，属于敏感数据：

- 只在可信设备和位置保存备份。
- 不要将原始聊天导出文件上传到公开 Issue 或网盘。
- 清理应用数据或卸载应用前，先导出需要保留的内容。
- 导入文件前确认其来源可信。

API Key 保存在应用私有配置中，不应通过截图或日志公开。

## 隐私、网络和费用

SoulBot 通过无障碍服务读取 Soul 当前向系统暴露的页面内容。生成回复时，相关聊天片段、用户填写的资料及已启用的参考内容可能发送给所配置的模型服务商。具体数据处理方式取决于所选择的服务商；模型调用可能产生费用。

联系人记忆和回放工具应按应用中的提示主动使用。不要向模型服务提交不希望第三方处理的内容。

## 常见问题

**模型测试失败**

检查 API 根地址是否正确、模型名称和 API Key 是否有效，并确认网络可访问该服务商。

**页面无法识别**

确认 Soul 已登录且位于支持的页面，重新开启无障碍服务，并在设备诊断页面检查识别结果。Soul 客户端更新可能改变页面结构。

**同城广场仍出现直播卡片**

检查应用是否为 2.2.0 或更高版本，并导出脱敏运行日志供定位。不同直播卡片样式可能暴露不同的无障碍节点；程序无法确认安全点击目标时应跳过卡片，而不是强行点击。若进入直播间后无法恢复，本轮广场浏览会停止。

**悬浮控制器不显示**

检查 Android 系统中的悬浮窗权限，以及系统是否限制 SoulBot 在后台运行。

**任务意外停止或联系人列表重复滑动**

检查无障碍服务、网络连接、电池优化和厂商后台管理设置，再查看应用内的运行日志。2.2.1 起，队列清空后应直接返回同城广场；如果联系人列表仍然反复滑动，请导出脱敏运行日志，重点检查是否存在尚未完成的队列任务或仍在运行的旧版本。如果队列显示发送状态待核验，请先确认 Soul 中是否已经发送，不要直接重复触发发送。

**聊天或记忆数据丢失**

卸载应用或清除应用数据可能删除本地内容。请使用此前导出的备份恢复；没有备份的本地数据可能无法找回。
